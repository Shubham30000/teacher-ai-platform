# Quality Refinement — Phase 2A Teaching Package

This is a **quality refinement only**. The architecture, ingestion pipeline,
parsing, chunking, embeddings, ChromaDB, retrieval, Educational
Classification, Knowledge Extraction, persistence, and API routes are all
unchanged. Every change below is inside the Phase 2A Teaching Package layer
(`app/teaching_package/`, `app/validation/validators.py`, and the prompt
templates under `prompts/`), matching what the Lesson Plan / Teacher Script /
Entry Ticket / Blackboard Notes / Activities / Assessment / Exit Ticket /
Homework / Teacher Guidance generators already did — no new generator
classes, no renamed files, no new microservices.

## Files changed

- `app/teaching_package/orchestrator.py` — run order + period propagation
- `app/teaching_package/base.py` — new `total_periods` parameter + `{{TOTAL_PERIODS}}` prompt variable
- `app/teaching_package/generators.py` — `TeacherGuidanceGenerator._parse` parses the new fields
- `app/teaching_package/models.py` — `TeacherGuidance` and `MisconceptionGuidance` gained new fields (all with safe defaults — backward compatible)
- `app/validation/validators.py` — new cross-module period-consistency check
- `prompts/*.md` — 8 of the 9 Teaching Package prompt templates updated (see below); `lesson_planner_prompt.md` got one clarifying sentence
- `tests/test_validators.py` — two new tests for the period-consistency check
- `README.md` — one paragraph in "Known limitations" updated because it described the exact problem Improvement 1 fixes

Nothing in `app/parsers/`, `app/chunking/`, `app/embeddings/`,
`app/vectorstore/`, `app/retriever/`, `app/classification/`,
`app/knowledge_extraction/`, `app/api/routes/`, or `app/teaching_package/persistence.py`
was touched.

## Improvement 1 — Global period consistency (highest priority)

**Before:** each of the 9 generators independently read the same
`KnowledgeJSON` and decided "a sensible number of periods" on its own. The
Lesson Plan might produce 3 periods while the Teacher Script produced 2 and
the Homework produced 4 — nine loosely related outputs instead of one
coherent package. (This was documented as a known limitation in `README.md`
before this change.)

**After:** the orchestrator now generates the **Lesson Plan first**, reads
`total_periods` off the result, and passes it into every remaining
generator's prompt as a new `{{TOTAL_PERIODS}}` variable
(`BaseTeachingGenerator._build_variables`, `orchestrator.py`). Every
period-numbered prompt (Entry Ticket, Teacher Script, Blackboard Notes,
Classroom Activity, Exit Ticket, Homework) now reads:

> Total teaching periods for this lesson: exactly 3 (fixed by the Lesson
> Plan, which is the single source of truth for period count and
> numbering — generate content for all of these periods, do not add or
> omit any, and use identical period numbering)

**Failure isolation is preserved.** If the Lesson Plan itself fails to
generate, the other 8 modules still run — they fall back to the old
"decide a sensible number yourself" instruction, exactly as before. A
Lesson Plan outage never blocks the rest of the package (see
`_format_total_periods` in `base.py` and the two branches in
`orchestrator.generate`).

**Assessment is intentionally not period-numbered.** The assignment
describes Assessment as one consolidated set of MCQs/short/long/numerical
questions with a rubric, and its schema has no `period_number` field. Adding
one would be a real schema change, which the task explicitly asked to avoid
unless "absolutely necessary." Instead, `assessment_prompt.md` now tells the
model the total period count and asks it to spread questions across the
whole chapter rather than concentrating on one part — same intent
(consistency with the Lesson Plan), no schema change.

**New validation:** `validate_teaching_package` now calls
`_validate_period_consistency`, which compares every period-numbered
module's period numbers against the Lesson Plan and raises a `warning`
(not an `error`, consistent with how a missing module is already only a
warning) if they don't match. This directly implements the assignment's
Stage 9 requirement — "consistency across periods" — which wasn't actually
checked before this change.

### Before / after (Class 8 "Force and Pressure", 3-period lesson)

| Module | Before | After |
|---|---|---|
| Lesson Plan | Period 1–3 | Period 1–3 |
| Entry Ticket | Period 1–2 (guessed independently) | Period 1–3 |
| Teacher Script | Period 1–4 (guessed independently) | Period 1–3 |
| Homework | Period 1–3 (coincidentally matched) | Period 1–3 |

## Improvement 2 — Motivation of the Day

`TeacherGuidance` gained `motivation_of_the_day: str` — one or two sentences
a teacher can open class with, generated by the existing Teacher Guidance
module (no new generator). The prompt requires it to reference the actual
topic, not a generic quote:

> **Before:** *(field did not exist)*
> **After** *(Force and Pressure)*: "A knife slices through vegetables
> easily while a spoon can't — the same small push, concentrated on a
> smaller area, becomes a much bigger effect. That's the idea we're
> exploring today."

## Improvement 3 — Today's Key Takeaway

`TeacherGuidance` gained `key_takeaway: str` — exactly one paragraph stating
the single biggest idea a student should remember after the whole chapter.

> **After** *(Force and Pressure)*: "Pressure is not the same thing as
> force — it's force spread over an area, so the same push can feel very
> different depending on how much surface it's concentrated on. That single
> idea explains everything from why a sharp knife cuts more easily than a
> blunt one to why wide skis keep you from sinking into snow."

## Improvement 4 — Learning Gap Analysis

`MisconceptionGuidance` (the existing per-misconception entry inside
`TeacherGuidance.misconception_guidance`) gained `diagnostic_question: str`,
alongside the fields it already had (`misconception`, `remedial_action`,
`severity`). This turns the existing misconception list into a proper
Learning Gap Analysis (assignment Stage 8: "diagnostic questions, severity
levels, and remedial actions for each gap") without introducing a new
top-level module — it's still grounded in `KnowledgeJSON`, per the FAQ's
answer on hallucination scope (secondary knowledge may improve pedagogy, but
subject-matter claims must stay traceable to the primary source).

> **Before:**
> ```json
> {"misconception": "Force and pressure are the same quantity.",
>  "remedial_action": "Contrast with worked examples.", "severity": "medium"}
> ```
> **After:**
> ```json
> {"misconception": "Force and pressure are the same quantity.",
>  "diagnostic_question": "If I push a wall with my palm flat, then with one
>    finger using the same force, does the pressure change? Why?",
>  "remedial_action": "Contrast with worked examples.", "severity": "medium"}
> ```

## Improvement 5 — Better teacher guidance

`TeacherGuidance` gained four new short bullet-list fields, each capped at
2–3 items in the prompt so they stay skimmable rather than turning into
another wall of text:

- `support_for_struggling_learners`
- `challenge_for_advanced_learners`
- `common_mistakes`
- `time_management_advice`

`teaching_tips` was tightened from "3-6 tips" to "2-3 tips" now that the
more specific categories above exist, to reduce overlap between fields.

## Improvement 6 — Less repetition

- The Teacher Guidance prompt now explicitly states each of its six
  list-type fields "serves a distinct purpose — do not restate the same
  sentence across multiple fields."
- The Blackboard Notes prompt now explicitly says not to restate the Lesson
  Plan's period summary — a blackboard note is a copyable list of
  terms/equations, not a paraphrase of the summary paragraph.

## Improvement 7 — Better classroom activities

`classroom_activity_prompt.md` now asks for a concept-tied `activity_type`
(demonstration, hands-on experiment, role play, concept mapping,
observation task, case study discussion, worksheet) and explicitly
discourages defaulting to "group discussion" unless the content is
genuinely discussion-based:

> **Before** *(generic)*: `"title": "Group Discussion", "activity_type":
> "group discussion", "instructions": "Discuss the concept of pressure in
> groups."`
> **After** *(concept-tied)*: `"title": "Balloon Squeeze: Force and
> Direction", "activity_type": "hands-on experiment", "instructions":
> "Give each group a balloon. Have them press it with one finger, then with
> a flat palm using the same effort, and compare how much the balloon
> deforms..."`

## Improvement 8 — Better assessment distribution

`assessment_prompt.md` now asks the model to spread questions across
concepts/periods "rather than asking multiple questions about the same
single concept while leaving others untested," and adds an explicit rule:
"Do not write two or more questions (across any of the four lists) that
test the exact same fact or concept in the same way." The existing
`short_answer`/`long_answer` split is reused to carry "very short recall"
vs. "reasoning/application" style questions (see Improvement 1 section
above for why no schema change was made here).

## Improvement 9 — Prompt quality

Every period-based prompt (Entry Ticket, Teacher Script, Blackboard Notes,
Classroom Activity, Exit Ticket, Homework) and the Assessment and Teacher
Guidance prompts had their CONTEXT section extended with the total-period
count and their RULES/TASK sections tightened for grounding and
consistency, per the sections above. All templates keep their existing
SYSTEM / CONTEXT / TASK / OUTPUT FORMAT / RULES (or VALIDATION RULES)
structure — no template was restructured, only the content within each
section.

## Testing

- All 9 Teaching Package generators, the orchestrator, and the validators
  keep their existing public signatures backward-compatible: `generate()`
  gained an *optional* `total_periods` parameter defaulting to `None`, and
  every new model field has a safe default (`""` or `[]`), so all existing
  calls and existing test fixtures (which don't pass the new fields) still
  construct valid objects.
- `tests/test_teaching_package_orchestrator.py`'s failure-isolation test
  (Lesson Plan fails, other 8 modules still succeed) continues to pass
  unchanged, since a failed Lesson Plan now falls back to `total_periods =
  None`, which renders the same "decide for yourself" instruction the
  templates used before this change.
- Added `tests/test_validators.py::test_validate_teaching_package_flags_period_mismatch`
  and `::test_validate_teaching_package_passes_when_periods_match` to cover
  the new `_validate_period_consistency` check directly.

This sandbox has no network access, so `pip install -r requirements.txt`
could not complete and the full `pytest` run could not be executed here.
Every changed file was verified with `python -m py_compile`, every prompt
template's `{{PLACEHOLDER}}` set was checked programmatically against the
variables `BaseTeachingGenerator._build_variables` actually supplies (all
resolve), and the orchestrator/generator/validator test files were traced
by hand against the new code path. Please run `pytest` in an environment
with dependencies installed before merging to get an authoritative pass/fail.
